# Ph.17 実装指示書 ─ モード切替時の画面描画改善

対象バージョン：V1.2.0  
作成日：2026-05-31

---

## 概要

モード切替ボタン（Normal ↔ Edit ↔ Settings）を押したとき、  
最終レイアウトが確定する前の**中間描画状態が一瞬画面に映り込む**問題を修正する。

BottomBar の行数変化・タイルグリッドの再構築・ウィンドウ高さ変更などが  
それぞれ独立した WPF レイアウトパスとして走るため、途中経過が視覚的に見えてしまう。

---

## 問題の詳細

### 切替時に発生する描画ステップ（例：Normal → Edit）

```
① BottomBar が 1 行 → 2 行に変化（高さ増加）
② ウィンドウ高さが伸びる
③ TileGridControl がタイルを再構築（編集オーバーレイ追加）
④ ページ編集ボタン・設定遷移ボタンが出現
```

各ステップが個別の `InvalidateMeasure()` / レイアウトパスとして描画されるため、  
「BottomBar だけ 2 行になってタイルがまだ通常モード」のような状態が画面に現れる。

---

## 実装方針

### アプローチ：コンテンツ一時非表示 + Dispatcher 同期

1. モード切替処理の**開始直前**にメインコンテンツを一時的に非表示にする。
2. すべてのレイアウト変更を通常通り実行する。
3. `Dispatcher.BeginInvoke(DispatcherPriority.Render, ...)` でレンダリングパスの完了後に再表示する。

WPF のディスパッチャー優先度は `Normal`(9) > `Render`(7) であるため、  
`Render` 優先度のコールバックは「全レイアウト変更がレンダリングスレッドに渡った後」に実行される。

```
[UI スレッド] ModeChange 開始 → コンテンツ非表示
            → PropertyChanged 伝播 → 各 UI 更新
            → Dispatcher.BeginInvoke(Render) をキュー
[レンダースレッド] レイアウト確定
[UI スレッド] コールバック実行 → コンテンツ再表示
```

## 実装内容

### 1. 非表示用オーバーレイの追加

**対象ファイル**

- `src/AppLauncher/Views/LauncherWindow.xaml`

モード切替中に最前面に被せる単色オーバーレイ（背景色と同色）を追加する。  
アニメーションなしで即時表示・非表示切り替えとする（フェード不要、チラつき防止が目的）。

```xml
<!-- モード切替中チラつき防止オーバーレイ（最前面に配置） -->
<Border x:Name="TransitionOverlay"
        Background="{Binding CurrentPage.BackgroundBrush}"
        Visibility="Collapsed"
        Panel.ZIndex="999"/>
```

> **代替案**：オーバーレイの代わりに `LauncherGrid.Opacity = 0` / `1` を切り替える方法も可。  
> ただし Opacity=0 でもヒットテストが有効なため、切替中のクリックを防ぐならオーバーレイが安全。

### 2. モード切替ラッパーの実装

**対象ファイル**

- `src/AppLauncher/Views/LauncherWindow.xaml.cs`

`LauncherViewModel.Mode` の `PropertyChanged` 通知を受けてオーバーレイを制御する。

```csharp
private void OnVmPropertyChanged(object? sender, PropertyChangedEventArgs e)
{
    if (e.PropertyName != nameof(LauncherViewModel.Mode)) return;
    // 既存のモード切替処理（ウィンドウ高さ変更等）はここで行われる

    // 全レイアウト変更が Dispatcher キューに積まれた後で表示を戻す
    Dispatcher.BeginInvoke(DispatcherPriority.Render, () =>
    {
        TransitionOverlay.Visibility = Visibility.Collapsed;
    });
}

// モード切替コマンド実行前（ViewModel 側で呼ばれる直前）にオーバーレイを表示
private void ShowTransitionOverlay()
{
    TransitionOverlay.Visibility = Visibility.Visible;
}
```

> `LauncherViewModel.ModeChanging`（イベント）を追加して呼び出す、または  
> ViewModel の `Mode` setter で `RequestModeChangeStart` アクションを経由して呼ぶ設計とする。

### 3. `LauncherViewModel` への切替前通知の追加

**対象ファイル**

- `src/AppLauncher/ViewModels/LauncherViewModel.cs`

```csharp
// Mode プロパティの setter に追加
public AppMode Mode
{
    get => _mode;
    set
    {
        if (_mode == value) return;
        ModeChanging?.Invoke();   // ← 追加：切替前通知
        _mode = value;
        OnPropertyChanged();
        // ... 既存処理 ...
    }
}

public event Action? ModeChanging;
```

`LauncherWindow` の `OnLoaded` で `vm.ModeChanging += ShowTransitionOverlay` を購読する。

### 4. オーバーレイ背景色のバインディング維持

**対象ファイル**

- `src/AppLauncher/Views/LauncherWindow.xaml`

ページ切り替え時に背景色が変わるため、`TransitionOverlay.Background` は  
現在ページの背景色にバインドする（切替前後で背景色が異なる場合を考慮）。

---

## 補足・設計上の注意

- **アニメーションは使用しない**：フェードなどを入れると逆に「遅い」と感じる場合があるため、即時切替を基本とする。ただし数十 ms のフェードを希望する場合は `DoubleAnimation` で `Opacity` を制御する変形版も可能。
- **ページ切り替え時は対象外**：ページ切り替えはタイルグリッドの部分更新のみで大きなレイアウト変化がないため、本フェーズの対象外とする。
- **収納アニメーション中の切替**：収納中のモード切替は現状でも制限がかかっているため影響なし。

## テスト観点

| # | 確認内容 | 期待結果 |
|---|---|---|
| 1 | Normal → Edit に切り替える | BottomBar 変化・タイル再構築の途中状態が見えない |
| 2 | Edit → Settings に切り替える | 仮想ページへの遷移途中が見えない |
| 3 | Settings → Normal に切り替える | 通常タイル復帰途中が見えない |
| 4 | ページ背景色が異なる状態で切り替える | オーバーレイ色が現在ページ色と一致している |
| 5 | 切替完了後に操作できる | オーバーレイが残留しない |
| 6 | 高速連打しても正常動作する | オーバーレイが詰まって残留しない |
