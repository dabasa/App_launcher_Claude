# Ph.16 実装指示書 ─ マルチディスプレイ対応強化

対象バージョン：V1.2.0  
作成日：2026-05-31

---

## 概要

マルチディスプレイ環境において、ランチャーウィンドウをディスプレイの境界付近に配置した場合、  
収納アニメーション中にウィンドウが**隣接ディスプレイへ貫通して表示されてしまう**問題を修正する。

修正後は、ウィンドウが吸着しているディスプレイの範囲外には  
**視覚的に表示されず・クリックも受け付けず・他のウィンドウの邪魔もしない**状態を保証する。

---

## 問題の詳細

### 発生条件

- 2台以上のディスプレイを横並びまたは縦並びで使用している
- ランチャーをディスプレイの境界に近い端に吸着させている
- 収納アニメーション（スライドアウト）を実行する

### 現象

```
┌─────────────┬─────────────┐
│  ディスプレイ1  │  ディスプレイ2  │
│             │  ┌─────┐   │
│             │  │ランチャー│   │ ← 収納時に境界を越えて貫通
│             │  └─────┘   │
└─────────────┴─────────────┘
              ↑ 境界
```

WPF ウィンドウはシステム座標空間全体を対象とするため、  
アニメーションで座標が隣接ディスプレイ領域に入るとそのまま描画・入力受付される。

### 影響範囲

| 影響 | 詳細 |
|---|---|
| 視覚 | 収納中・収納後に隣ディスプレイへランチャーが見える |
| 入力 | 隣ディスプレイ上のランチャー領域がクリック可能になる |
| 他ウィンドウ | 最前面設定のため、隣ディスプレイの操作を妨げる可能性がある |

---

## 実装方針

### アプローチ：Win32 `SetWindowRgn` によるウィンドウ表示領域クリッピング

WPF ウィンドウの**表示領域（ウィンドウリージョン）** を、  
吸着しているディスプレイの矩形と一致するよう動的に設定する。

`SetWindowRgn` を適用すると、リージョン外の部分は：
- 描画されない（透明ではなく、存在しない）
- マウス入力を受け付けない
- 他のウィンドウの前面に割り込まない

```
ウィンドウ全体矩形（WPF 座標）
┌──────────────────┐
│                  │
│  クリップ領域      │ ← SetWindowRgn で this monitor に制限
│  （monitor 範囲内）│
│                  │
└──────────────────┘
  ↑ リージョン外は非表示・非入力
```

### 代替案（不採用理由）

| 案 | 不採用理由 |
|---|---|
| アニメーション終点をディスプレイ内に収める | ハンドルが境界に触れている場合、完全に隠れてしまう |
| `ClipToBounds` プロパティ | WPF 要素内のクリッピングのみ。ウィンドウ座標には効かない |
| ウィンドウを別モニターに移動しない制限 | 元々ウィンドウ自体は移動するため根本解決にならない |

## 実装内容

### 1. 現在のモニター情報取得ユーティリティの追加

**対象ファイル**

- `src/AppLauncher/Helpers/MonitorHelper.cs`（新規）

吸着中のモニター矩形を取得するヘルパーを実装する。  
既存の `SnapService` が `snapMonitor` を保持しているため、そこから取得する。

```csharp
public static class MonitorHelper
{
    /// <summary>指定ウィンドウが属するモニターの作業領域を WPF デバイス非依存単位で返す。</summary>
    public static Rect GetMonitorWorkArea(Window window)
    {
        var hwnd   = new System.Windows.Interop.WindowInteropHelper(window).Handle;
        var hMon   = NativeMethods.MonitorFromWindow(hwnd, MONITOR_DEFAULTTONEAREST);
        var info   = new MONITORINFO { cbSize = Marshal.SizeOf<MONITORINFO>() };
        NativeMethods.GetMonitorInfo(hMon, ref info);

        // rcWork は物理ピクセル → WPF の DIP に変換
        var source = PresentationSource.FromVisual(window);
        double dpiX = source?.CompositionTarget?.TransformFromDevice.M11 ?? 1.0;
        double dpiY = source?.CompositionTarget?.TransformFromDevice.M22 ?? 1.0;

        return new Rect(
            info.rcWork.Left   * dpiX,
            info.rcWork.Top    * dpiY,
            (info.rcWork.Right  - info.rcWork.Left) * dpiX,
            (info.rcWork.Bottom - info.rcWork.Top)  * dpiY);
    }
}
```

### 2. `SetWindowRgn` によるリージョン適用

**対象ファイル**

- `src/AppLauncher/Services/SnapService.cs`  
  または `src/AppLauncher/Views/LauncherWindow.xaml.cs`

ウィンドウ位置が変わるたびに、ウィンドウ矩形とモニター矩形の交差部分を計算して  
`SetWindowRgn` で適用する。

```csharp
private void ApplyMonitorClip()
{
    var monitorRect = MonitorHelper.GetMonitorWorkArea(_window);
    var windowRect  = new Rect(_window.Left, _window.Top, _window.Width, _window.Height);

    // モニター矩形をウィンドウローカル座標に変換
    var clip = Rect.Intersect(monitorRect, windowRect);
    if (clip.IsEmpty) { ClearWindowRegion(); return; }

    double offsetX = clip.X - windowRect.X;
    double offsetY = clip.Y - windowRect.Y;

    // 物理ピクセルに変換（SetWindowRgn はピクセル単位）
    var source = PresentationSource.FromVisual(_window);
    double scaleX = source?.CompositionTarget?.TransformToDevice.M11 ?? 1.0;
    double scaleY = source?.CompositionTarget?.TransformToDevice.M22 ?? 1.0;

    int x = (int)(offsetX * scaleX);
    int y = (int)(offsetY * scaleY);
    int w = (int)(clip.Width  * scaleX);
    int h = (int)(clip.Height * scaleY);

    var hRgn = NativeMethods.CreateRectRgn(x, y, x + w, y + h);
    var hwnd = new WindowInteropHelper(_window).Handle;
    NativeMethods.SetWindowRgn(hwnd, hRgn, true);
    NativeMethods.DeleteObject(hRgn);
}

private void ClearWindowRegion()
{
    var hwnd = new WindowInteropHelper(_window).Handle;
    NativeMethods.SetWindowRgn(hwnd, IntPtr.Zero, true);
}
```

### 3. `NativeMethods` への Win32 宣言追加

**対象ファイル**

- `src/AppLauncher/Helpers/NativeMethods.cs`（既存ファイルに追記）

```csharp
[DllImport("gdi32.dll")]
public static extern IntPtr CreateRectRgn(int x1, int y1, int x2, int y2);

[DllImport("gdi32.dll")]
public static extern bool DeleteObject(IntPtr hObject);

[DllImport("user32.dll")]
public static extern int SetWindowRgn(IntPtr hWnd, IntPtr hRgn, bool bRedraw);

[DllImport("user32.dll")]
public static extern IntPtr MonitorFromWindow(IntPtr hwnd, uint dwFlags);

[DllImport("user32.dll")]
public static extern bool GetMonitorInfo(IntPtr hMonitor, ref MONITORINFO lpmi);

public const uint MONITOR_DEFAULTTONEAREST = 2;

[StructLayout(LayoutKind.Sequential)]
public struct MONITORINFO
{
    public int   cbSize;
    public RECT  rcMonitor;
    public RECT  rcWork;
    public uint  dwFlags;
}
```

### 4. クリップ更新タイミング

`ApplyMonitorClip()` を以下のタイミングで呼び出す。

| タイミング | 呼び出し元 |
|---|---|
| ウィンドウ位置が変わるたび（アニメーション中を含む） | `LauncherWindow` の `LocationChanged` イベント |
| 収納・展開アニメーション開始時 | `SnapService.Retract()` / `SnapService.Extend()` の前後 |
| 吸着モニターが変更されたとき | `SnapService.ApplySnap()` 完了後 |
| ウィンドウ初期化後 | `LauncherWindow.OnLoaded` |

### 5. シングルディスプレイ環境での非影響確認

シングルディスプレイ環境ではモニター矩形とウィンドウ矩形が常に交差するため、  
`SetWindowRgn` はウィンドウ全体を含む矩形を設定するだけになり動作に影響しない。  
ただし、角丸表示（`AllowsTransparency = true` + `WindowStyle = None` の組み合わせ）との  
干渉の有無を確認すること（`SetWindowRgn` は角丸クリッピングを上書きする可能性がある）。

> **注意**：既存の `AllowsTransparency = true` 設定下では `SetWindowRgn` が無効な場合がある。  
> その場合は、WPF の `Clip` プロパティ（`RectangleGeometry`）を用いた代替実装を検討する。

---

## 代替実装（`AllowsTransparency` との競合時）

`SetWindowRgn` が機能しない場合、WPF レイヤーでの対処として以下を検討する。

```csharp
// ウィンドウのルートグリッドに Clip を設定する
var clipRect = /* モニター範囲をウィンドウ座標に変換した Rect */;
RootGrid.Clip = new RectangleGeometry(clipRect);
```

この方法は視覚的クリッピングのみ有効で、入力（マウスクリック）まで遮断できるかは検証が必要。  
入力遮断も必要な場合は `IsHitTestVisible = false` を組み合わせる、  
または `WS_EX_TRANSPARENT` を用いた透過ウィンドウ重ね合わせを検討する。

## テスト観点

| # | 確認内容 | 期待結果 |
|---|---|---|
| 1 | 2ディスプレイ環境で境界付近に吸着させて収納する | 隣ディスプレイにランチャーが表示されない |
| 2 | 収納後に隣ディスプレイ側をクリックする | ランチャーがクリックを受け付けない |
| 3 | 収納後に隣ディスプレイのウィンドウを操作する | ランチャーが邪魔せず操作できる |
| 4 | 展開アニメーション中も隣ディスプレイに見えない | アニメーション全体を通じて貫通しない |
| 5 | シングルディスプレイ環境で動作確認する | 従来通りの表示・動作が維持される |
| 6 | 吸着モニターを切り替えた後に収納する | 新しいモニターのクリップが正しく適用される |
| 7 | 角丸表示が維持される | `SetWindowRgn` による角丸崩れがない |
