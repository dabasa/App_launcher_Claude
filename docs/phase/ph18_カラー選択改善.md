# Ph.18 実装指示書 ─ カラー選択方式の改善（カスタム色追加）

対象バージョン：V1.1.0  
作成日：2026-05-24

---

## 概要

カラー選択プルダウンの末尾に「カスタム」項目を追加する。  
カスタム選択時はカラーピッカーを起動し、任意の色を 1 件保存できる。

---

## 実装内容

### 1. カラーピッカーの導入

WPF 標準にはカラーピッカーコントロールがないため、以下のいずれかを採用する。

**推奨方式**

- **Ookii.Dialogs.Wpf** など軽量ライブラリのカラーダイアログを使用する。
- または、シンプルな自作カラーピッカーダイアログ（`#RRGGBB` hex 入力 ＋ RGB スライダー）を実装する。

実装が簡単な方を選択してよい。

### 2. カラー選択プルダウンの変更

**対象ファイル**

- カラー選択プルダウンを生成しているコントロール（`ColorComboBox` 等）の全箇所

**変更内容**

1. カラーパレット 11 色の選択肢の末尾に「カスタム」項目を追加する。
2. 「カスタム」項目には `customColor` の現在値のカラーブロックを横に表示する（未設定時はグレーなどの空欄表示）。
3. 「カスタム」が選択されたとき、カラーピッカーを起動する。
4. ピッカーで色が確定（OK）されたとき：
   - `config.json` の `customColor` を更新する。
   - そのカラー設定項目に選択した色を反映する。
5. ピッカーがキャンセルされたとき：
   - 直前に選択していたカラーに戻す。

### 3. `customColor` の Model / Service 対応

**対象ファイル**

- `src/AppLauncher/Models/AppConfig.cs`（または相当するルートモデルクラス）
- `src/AppLauncher/Services/ConfigService.cs`

**変更内容**

```csharp
public class AppConfig
{
    public GlobalConfig Global { get; set; } = new();
    public LayoutConfig Layout { get; set; } = new();
    public List<PageConfig> Pages { get; set; } = new();
    public string? CustomColor { get; set; } = null;   // 追加
    public List<TileStyleConfig> TileStyles { get; set; } = new(DefaultTileStyles);
    public List<PageStyleConfig> PageStyles { get; set; } = new(DefaultPageStyles);
}
```

- `customColor` は `null` または hex 文字列（`"#RRGGBB"`）。
- 保存・読み込みは既存の `ConfigService.SaveAsync()` / `LoadAsync()` に自動的に含まれる（JSON シリアライズ）。

### 4. カラー値の内部表現の変更

**重要**：既存の色設定は「カラーパレット名（文字列）」で保存されている。  
カスタム色は hex 値であり、パレット名ではない。

タイル・ページの色設定フィールド（`color` / `fontColor` 等）は現在 `string` 型で、  
`"blue"` などのパレット名か、将来的に `"#RRGGBB"` のいずれかの値を持つことになる。

`ColorPalette.GetColor()` メソッドを以下のように拡張する：

```csharp
public static Color GetColor(string colorNameOrHex)
{
    // hex 形式（"#RRGGBB"）であれば直接パース
    if (colorNameOrHex.StartsWith('#'))
        return (Color)ColorConverter.ConvertFromString(colorNameOrHex);

    // パレット名であれば既存のマッピングから取得
    return _palette.TryGetValue(colorNameOrHex, out var c) ? c : Colors.Gray;
}
```

### 5. カスタム色が未設定の場合の動作

- `customColor` が `null` の場合、「カスタム」項目のカラーブロックはグレー（または「未設定」の表示）とする。
- 「カスタム」を選択しピッカーで色を確定すると、初めて `customColor` が設定される。

## テスト観点

| # | 確認内容 | 期待結果 |
|---|---|---|
| 1 | カラープルダウンを開く | 11 色 ＋「カスタム」が表示される |
| 2 | 「カスタム」を選択する | カラーピッカーが起動する |
| 3 | ピッカーで色を確定する | タイルに選択した色が反映される |
| 4 | ピッカーをキャンセルする | 直前の色に戻る |
| 5 | 別の色でカスタムを確定する | `customColor` が上書きされる（1 件のみ） |
| 6 | config.json に `customColor` を保存し再起動する | 再起動後も「カスタム」が正しい色で表示される |
| 7 | `customColor` が `null` の状態で「カスタム」項目を確認する | カラーブロックが空欄・グレー等で表示される |
