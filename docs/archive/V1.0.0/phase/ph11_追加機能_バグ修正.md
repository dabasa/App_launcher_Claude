### 1. タイルコピー機能

**対象ファイル**

| ファイル | 変更内容 |
|---|---|
| `Views/Controls/TileGridControl.xaml.cs` | `_copyingTile` フィールド追加、コピーモード分岐追加 |
| `Views/Controls/TileControl.xaml.cs` | コピーボタン（⊕）の MouseLeftButtonUp ハンドラ追加 |

**動作仕様**

1. 編集モードでタイルにホバーすると左下にコピーボタン（⊕）が表示される。
2. コピーボタンを押すと `_copyingTile` にコピー元タイルを保持し、コピーモードに移行する。
3. コピーモード中に `OnTileGridMouseMove` でカーソル位置のセルを計算し、配置プレビュー枠を表示する。
4. 空きセルをクリックすると、元タイルの設定を引き継いだ **1×1** の新規タイルを配置する。
5. 右クリックでコピーモードをキャンセルし `_copyingTile = null` にする。

### 2. ドラッグ中のページインジケーターホバーでのページ切り替え

**対象ファイル**

| ファイル | 変更内容 |
|---|---|
| `Views/Controls/BottomBarControl.xaml.cs` | `_dragSwitchTimer`・`_dragSwitchTargetIndex` フィールド追加、`StartDragSwitchTimer`・`StopDragSwitchTimer` メソッド追加、`RebuildIndicators` に `AllowDrop=true`・ハイライト・DragEnter/DragLeave/Drop ハンドラを追加 |

**実装詳細**

```csharp
private DispatcherTimer? _dragSwitchTimer;
private int              _dragSwitchTargetIndex;

private void StartDragSwitchTimer(int pageIndex)
{
    StopDragSwitchTimer();
    if (_vm == null || pageIndex == _vm.CurrentPageIndex) return;
    _dragSwitchTargetIndex = pageIndex;
    _dragSwitchTimer = new DispatcherTimer { Interval = TimeSpan.FromMilliseconds(700) };
    _dragSwitchTimer.Tick += (_, _) =>
    {
        StopDragSwitchTimer();
        _vm?.NavigateToPageCommand.Execute(_dragSwitchTargetIndex);
    };
    _dragSwitchTimer.Start();
}
```

各インジケーターに追加するハンドラ：

```csharp
indicator.AllowDrop = true;
indicator.DragEnter += (_, _) => { highlight.Visibility = Visibility.Visible;  StartDragSwitchTimer(idx); };
indicator.DragLeave += (_, _) => { highlight.Visibility = Visibility.Collapsed; StopDragSwitchTimer(); };
indicator.Drop      += (_, _) => { highlight.Visibility = Visibility.Collapsed; StopDragSwitchTimer(); };
```

### 3. ページ間タイル移動のバグ修正

**問題**：ドラッグ中にページを切り替えて別ページのグリッドへドロップしてもタイルが移動元ページに残ったまま新ページに追加されなかった。

**対象ファイル**：`Views/Controls/TileGridControl.xaml.cs`

**修正内容**

`OnTileGridDrop` に `FindPageContaining` を使ったページ間移動ロジックを追加：

```csharp
var sourcePage = FindPageContaining(drag);
if (sourcePage != null && sourcePage != destPage)
{
    if (!CanPlace(col, row, drag.ColSpan, drag.RowSpan)) return;
    sourcePage.Tiles.Remove(drag);
    drag.Col = col;
    drag.Row = row;
    destPage.Tiles.Add(drag);
    Rebuild();
    return;
}

private static PageViewModel? FindPageContaining(TileViewModel tile)
    => App.LauncherViewModel?.Pages.FirstOrDefault(p => p.Tiles.Contains(tile));
```

private void UpdateSiTargetCombo()
{
    var vm = _subscribedTileVm;
    if (vm == null) return;
    IEnumerable<string>? items = null;
    if (vm.SiCategory == "storage")
        items = SystemInfoService.GetDriveTargets();
    else if (vm.SiCategory == "usage" && vm.SiDeviceType == "lan")

        items = SystemInfoService.GetGpuTargets();

        SiTargetCombo.ItemsSource = items.ToList();
}

### 5. GPU 使用率の実装

**対象ファイル**：`Services/SystemInfoService.cs`

**実装方式**：WMI `Win32_PerfFormattedData_GPUPerformanceCounters_GPUEngine`

PerformanceCounter 方式はインスタンスが GPU を使用しているプロセスごとに生成・消滅するため、プライミング後にインスタンスが消えてしまい 0% になる問題があった。WMI の PerfFormattedData はクエリごとに差分レートを計算して返すため、この問題を回避できる。

```csharp
private SystemData GetGpuData(SystemInfoConfig cfg)
{
    int    physIndex = ParseGpuPhysIndex(cfg.Target);
    string gpuName   = GetGpuName(physIndex);
    double pct       = ReadGpuUsageWmi(physIndex);
    return new SystemData($"GPU {pct:F1} %", gpuName, pct, pct >= cfg.Threshold);
}

private static double ReadGpuUsageWmi(int physIndex)
{
    try
    {
        string physTag = $"phys_{physIndex}_";
        using var s = new ManagementObjectSearcher(
            "SELECT Name, UtilizationPercentage " +
            "FROM Win32_PerfFormattedData_GPUPerformanceCounters_GPUEngine");
        double total = 0;
        foreach (ManagementObject o in s.Get())
        {
            string? name = o["Name"]?.ToString();
            if (name == null || !name.Contains(physTag) || !name.Contains("engtype_3D")) continue;
            total += Convert.ToDouble(o["UtilizationPercentage"]);
        }
        return Math.Min(100.0, total);
    }
    catch { return 0; }
}
```

GPU インスタンス名の形式：`pid_XXXX_luid_..._phys_0_eng_X_engtype_3D`。`phys_(\d+)` で物理 GPU インデックスを抽出し、`engtype_3D` のエンジンの使用率を合算する。

**選択肢の生成（`GetGpuTargets`）**：WMI からインデックスを列挙して `phys_X  GPU名` 形式の文字列リストを返す。

### 6. LAN 速度表示（PerformanceCounter キャッシュ方式）

**対象ファイル**：`Services/SystemInfoService.cs`

**問題**：WMI `Win32_PerfFormattedData_Tcpip_NetworkInterface` 方式ではレートカウンターが毎回新しい接続で前サンプルなしになるため、常に 0 を返していた。

**実装方式**：`PerformanceCounter("Network Interface", "Bytes Received/sec", instName)` をインスタンス名ごとにキャッシュ。

```csharp
private readonly Dictionary<string, (PerformanceCounter rx, PerformanceCounter tx)> _lanCounters = new();

private SystemData GetLanData(SystemInfoConfig cfg)
{
    string instName = ResolveLanInstance(cfg.Target);
    bool isNew;
    (PerformanceCounter rx, PerformanceCounter tx) pair;
    lock (_lock)
    {
        isNew = !_lanCounters.TryGetValue(instName, out pair);
        if (isNew)
        {
            var rxC = new PerformanceCounter("Network Interface", "Bytes Received/sec", instName, true);
            var txC = new PerformanceCounter("Network Interface", "Bytes Sent/sec",     instName, true);
            rxC.NextValue(); txC.NextValue(); // プライミング
            pair = (rxC, txC);
            _lanCounters[instName] = pair;
        }
    }
    if (isNew) return new SystemData("↓ - KB/s  ↑ - KB/s", instName, 0, false);

    float rx, tx;
    lock (_lock) { rx = pair.rx.NextValue(); tx = pair.tx.NextValue(); }
    return new SystemData($"↓{rx / 1024.0:F0} KB/s  ↑{tx / 1024.0:F0} KB/s", instName, 0, false);
}
```

**インターフェース名の解決（`ResolveLanInstance`）**：`PerformanceCounterCategory("Network Interface").GetInstanceNames()` から完全一致 → 部分一致 → 逆部分一致の順でマッチング。

**初回呼び出し**：カウンターのプライミング（`NextValue()` が 0 を返す仕様）のため「↓ - KB/s  ↑ - KB/s」と表示する。

### 7. システムタイルデータ取得の非同期化

**対象ファイル**：`Views/Controls/SystemTileControl.xaml.cs`

**問題**：タイルロード時の `FetchAndUpdate()` が UI スレッドで WMI/PerformanceCounter を呼び出すため、ページ切り替え時に 1 秒程度の遅延が発生していた。

**修正内容**：`FetchAndUpdate` を `async void` + `Task.Run` に変更し、バックグラウンドスレッドで取得。ページ切り替えで別タイルになった場合の古い結果は `if (_si == si)` チェックで破棄する。

```csharp
private async void FetchAndUpdate()
{
    if (_si == null || _tile == null) return;
    var si   = _si;
    var data = await Task.Run(() => SystemInfoService.Instance.GetData(si));
    if (_si == si) Render(data);  // ページ切り替えで変わっていたら破棄
}
```

**スレッド安全性**：`SystemInfoService` 内のすべての可変共有状態（`_cpuTotal`・`_gpuNames`・`_lanCounters`）は `_lock` オブジェクトで保護している。
